# Story 3.3: Trade Lifecycle Management

## Status
Ready for Development

## Story
**As a** trader,
**I want** automatic management of my trades from entry to exit,
**so that** I can rely on systematic execution without manual intervention.

## Acceptance Criteria

1. Entry function monitored while position is flat (TradePlanStatus.awaiting_entry)
2. Upon entry trigger, position size calculated using existing risk management module
3. Risk checks performed before order submission (portfolio limit validation)
4. After successful risk validation and fill, stop-loss and take-profit orders placed immediately
5. Position added to risk registry with calculated risk amount upon fill
6. Exit functions (stop/target) monitored while position is open (TradePlanStatus.position_open)
7. Position state tracked through lifecycle: awaiting_entry → position_open → position_closed
8. Exit fills cancel any remaining orders for that symbol and remove position from risk registry

### Architecture Considerations

**State Machine Design:**
```python
class TradeLifecycleState(Enum):
    AWAITING_ENTRY = "awaiting_entry"
    POSITION_OPEN = "position_open" 
    POSITION_CLOSED = "position_closed"
    ERROR = "error"
    CANCELLED = "cancelled"

class TradeOrchestrator:
    async def process_market_data(self, bar_data: BarData) -> None:
        """Process bar data and evaluate appropriate functions based on trade state."""
        
    async def handle_entry_signal(self, signal: ExecutionSignal, trade_plan: TradePlan) -> None:
        """Handle entry signals with risk validation and order placement."""
        
    async def handle_exit_signal(self, signal: ExecutionSignal, trade_plan: TradePlan) -> None:
        """Handle exit signals with order cancellation and position cleanup."""
```

**Performance Requirements:**
- Signal to order submission latency: <1 second (per NFR1)
