# Story 3.4: Simulation Mode

## Status
Completed

## Story
**As a** trader,
**I want** a simulation mode that feeds pre-recorded market data through the system exactly as live data would flow,
**so that** I can validate my trading logic against known historical scenarios without connecting to IBKR.

## Acceptance Criteria

1. System supports pluggable data feed providers via abstract interface
2. File-based data feed reads OHLCV data from CSV/YAML/JSON files
3. The system operates identically whether receiving live or file-based data (TradeOrchestrator is agnostic)
4. Simulated order execution (using existing `OrderSimulationEngine`) completes successfully with configurable behavior
5. Clear simulation indicators in all output (logs, Discord, CLI status)
6. Environment variable or config controls simulation mode (`SIMULATION_MODE=true`)
7. Support for playback speed control (instant replay, real-time simulation, fast-forward)
8. All logging, notifications, and state persistence operate normally

### Architecture Analysis

**Key Insight: TradeOrchestrator is Source-Agnostic**
```python
# TradeOrchestrator just receives BarData - doesn't care where it came from
async def process_market_data_event(self, bar_data: BarData) -> None:
    """Process incoming market data and evaluate relevant trade plans."""
```

This is the natural abstraction seam we exploit.

### Component Architecture

**DataFeedProvider Protocol:**
```python
from typing import Protocol, Callable
from auto_trader.models.market_data import BarData

class DataFeedProvider(Protocol):
    """Abstract interface for market data providers.
    
    Implementations must distribute BarData objects to registered
    subscribers. The system is agnostic to the data source.
    """
    
    def add_subscriber(
        self, subscriber_id: str, callback: Callable[[BarData], None]
    ) -> None:
        """Register a callback to receive BarData updates."""
        ...
    
    def remove_subscriber(self, subscriber_id: str) -> bool:
        """Unregister a subscriber. Returns True if found."""
        ...
    
    async def start(self) -> None:
        """Start feeding data to subscribers."""
        ...
    
    async def stop(self) -> None:
        """Stop feeding data."""
        ...
    
    async def subscribe_symbols(
        self, symbols: list[str], bar_sizes: list[str]
    ) -> dict[str, bool]:
        """Subscribe to specific symbols and timeframes."""
        ...
```

**FileDataFeed Implementation:**
```python
class FileDataFeed:
    """File-based data feed for simulation mode.
    
    Reads OHLCV data from files and distributes as BarData objects
    to subscribers, simulating live market data flow.
    """
    
    def __init__(
        self,
        file_path: str,
        playback_mode: PlaybackMode = PlaybackMode.SEQUENTIAL,
        speed_multiplier: float = 1.0,
    ):
        ...
    
    async def start(self) -> None:
        """Begin playback of file data."""
        for bar_data in self._load_bars_from_file():
            await self._distribute_to_subscribers(bar_data)
            if self.playback_mode == PlaybackMode.REAL_TIME:
                await asyncio.sleep(self._calculate_delay(bar_data))
```

**File Format Examples:**

CSV format - Standard (`simulation_data.csv`):
```csv
timestamp,symbol,open,high,low,close,volume,bar_size
2024-12-01T09:30:00Z,SPY,450.00,450.50,449.80,450.25,1000000,5min
2024-12-01T09:35:00Z,SPY,450.25,451.00,450.10,450.75,1200000,5min
```

CSV format - Yahoo Finance style (requires ColumnMapping):
```csv
Date,Open,High,Low,Close,Adj Close,Volume
2006-01-03 00:00:00,2.585,2.669,2.580,2.669,2.257,807234400
```

**ColumnMapping Usage:**
```python
from auto_trader.data_feed import FileDataFeed, ColumnMapping, PlaybackMode

# For Yahoo Finance / Alpha Vantage style files

feed = FileDataFeed(
```

### Integration Points

**TradingApplication Changes:**
```python
class TradingApplication:
    def __init__(self, settings: Settings):
        # Factory pattern based on simulation mode
        if settings.simulation_mode:
            self.data_feed = FileDataFeed(settings.simulation_data_file)
            self.order_provider = SimulatedOrderExecution()
        else:
            self.data_feed = IBKRDataFeed(self.ibkr_client)
            self.order_provider = IBKROrderExecution(self.ibkr_client)
```

**Existing OrderSimulationEngine:**
The system already has `OrderSimulationEngine` in `integrations/ibkr_client/order_simulation_engine.py` providing:
- `place_market_order()` - Immediate simulated fill
- `place_bracket_order()` - Simulated bracket with stop/profit orders
- `modify_order()` - Simulated modifications
- `cancel_order()` - Simulated cancellations

This is **already implemented** and provides simplistic, always-successful execution - exactly what's needed for logic validation.

### Design Philosophy

**Goal: Logic Validation, Not Realistic Simulation**

This simulation mode is intentionally simple:
- Orders always fill successfully at expected prices
- No slippage, partial fills, or rejections (unless explicitly testing those scenarios)
- Focus is on validating execution function logic (close_above, close_below, etc.)
- Verify state transitions, position management, and risk calculations

Realistic backtesting with slippage, latency, and market impact is a **separate, future concern**.

### Testing Strategy

**Unit Tests:**
- FileDataFeed file parsing (CSV, YAML, JSON)
- BarData validation for file-loaded data
- Playback mode timing accuracy
- Protocol compliance for all implementations

**Integration Tests:**
- End-to-end simulation: file data → TradeOrchestrator → signal → simulated order
- State persistence works identically in simulation mode
- Risk calculations use simulated position data correctly

**Scenario Tests:**
- Entry trigger scenarios (close_above, close_below)
- Exit scenarios (stop loss hit, take profit hit)
- Position lifecycle (entry → holding → exit)
- Multiple concurrent plans

### Success Criteria

- Trade plan evaluation logic works identically with file data vs live data
- Developers can create reproducible test scenarios using data files
- Existing unit tests can leverage simulation mode for realistic integration testing
- No risk of accidental live orders when in simulation mode
- Clear visual distinction between simulation and live modes everywhere
- System startup time significantly faster in simulation mode (no IBKR connection)

### Future Considerations (Out of Scope)

- Realistic slippage simulation
- Partial fills and order rejections
- Market impact modeling
- Historical data recording from live sessions for replay
- Performance backtesting with P&L metrics
- Strategy optimization with parameter sweeping

These belong in a dedicated backtesting epic, not simulation mode.
