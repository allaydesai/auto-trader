# Story 4.3: State Persistence and Recovery

## Status
Not Started

## Story
**As a** trader,
**I want** my positions and system state to survive restarts and crashes,
**so that** I can maintain trades across multiple days and recover gracefully from system failures.

## Acceptance Criteria

1. Position state saved to JSON file on every state change with atomic writes
2. State includes: symbol, entry_price, size, stop/target order IDs, entry_time, current P&L
3. On startup, state file loaded and positions reconciled with IBKR current positions
4. Orphaned orders detected and cancelled if position no longer exists in IBKR
5. State file backup created before each update (rotating last 5 versions)
6. Recovery process logged comprehensively showing what was restored vs rejected
7. Risk management state restored: portfolio risk tracking and position registry
8. Recovered positions validated against current portfolio risk limits before restoration

### Recovery Process Design

**Startup Recovery Workflow:**
1. **Load State File:** Read position state with validation and error handling
2. **Query IBKR:** Get current positions and open orders from broker
3. **Reconcile Positions:** Compare saved state with IBKR reality
4. **Validate Risk:** Check recovered positions against current risk limits
5. **Clean Orphaned Orders:** Cancel orders without corresponding positions
6. **Restore Risk Registry:** Update portfolio risk tracking with recovered positions
7. **Log Results:** Comprehensive logging of recovery decisions and actions

**Position Reconciliation Logic:**
```python
async def reconcile_position(self, saved_pos: PositionStateSnapshot, ibkr_pos: Optional[IBKRPosition]) -> ReconciliationAction:
    """Determine appropriate action for position reconciliation."""
    
    if not ibkr_pos:
        # Position closed at broker but still in saved state
        return ReconciliationAction.MARK_CLOSED
        
    if saved_pos.size != ibkr_pos.size:
        # Position size mismatch - partial fill or additional entry
        return ReconciliationAction.UPDATE_SIZE
        
    if abs(saved_pos.entry_price - ibkr_pos.avg_price) > 0.01:
        # Price mismatch - update to broker reality
        return ReconciliationAction.UPDATE_PRICE
        
    return ReconciliationAction.RESTORE_NORMAL
```

### Performance and Reliability

**Atomic Operations:**
- All state saves use atomic write operations (write to temp, then rename)
- File locking to prevent corruption from concurrent access
- Backup creation before any state modification

**Performance Optimization:**
- Debounced state saves to prevent excessive I/O during rapid updates
- Incremental backups when possible to reduce disk usage
- Efficient JSON serialization with minimal memory footprint

**Error Recovery:**
- Graceful handling of corrupted state files with backup fallback
- Partial recovery support when some positions can be restored
- Clear error messages and recovery recommendations
